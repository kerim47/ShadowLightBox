## What the app does

A wall-mounted **shadow lamp** has a light at its centre and a thin printed wall around it. Light only reaches the room wall through holes in that wall, so the wall casts a picture on the wall around the lamp. The app runs this in reverse:

1. Take a photo, an SVG or a hand-drawn image, and turn it into a **target image**: white = lit on the room wall, black = shadow.
2. For every point of the lamp's wall, trace the ray from the LED through that point to the room wall (inverse projection). Read the target there: lit means cut a hole, dark means keep material.
3. Mesh the result into a **watertight, printable STL**: wall, base plate with keyhole, and an LED holder. Fix printability on the way: bridge loose parts, add support-free overhang roofs, chamfer flat panels.

## Run / test

```bash
npm install                         # npm 11+ skips install scripts; if Electron is missing:
node node_modules/electron/install.js
npm start                           # electron . --no-sandbox (Linux SUID sandbox workaround)
npm test                            # geometry core tests, plain Node, ~30 s — MUST stay green
```

- `npm test` (`tests/run-tests.js`) loads the core modules into Node and checks:
  - projection round-trips, and parity with the original box formula;
  - watertightness of every mesh for all shapes × print modes × mounts;
  - structural rules: bridges, floating front rim, overhang roofs, 45° chamfer, keyhole placement, far-edge smoothness;
  - the converter core (stencil print check, contours, SVG);
  - every export format written and read back, and light-part separation.
- There is no UI test runner. For visual checks, write a small Electron harness: `require('electron/main.cjs')`, then drive the page with `webContents.executeJavaScript` and capture with `capturePage()`.
  - Call `webContents.setBackgroundThrottling(false)` and `win.show()` before capturing. Background windows don't paint new frames, so screenshots come out stale.
  - Don't write into the user's Downloads during checks (cancel the export dialog).

## Core conventions

- **No bundler, no ES modules.** Each `renderer/src/*.js` is an IIFE that attaches one global (`Shapes`, `Projection`, `WallField`, `ShellMesher`, `ModelExport`, `Stencil`, `Silhouette`, `Designer`, `Geometry`, `ModelImport`, `DesignStorage`, `FilePicker`, `SilhouetteEditor`, `ImageConverter`, `MenuBar`, `Inspector`, `HelpTips`; `main.js` sets none). The core uses `typeof window !== 'undefined' ? window : globalThis` so Node tests can load it. Script order in `index.html` matters.
  - The core modules are `shapes`, `projection`, `wall_field`, `shell_mesher`, `exporters` and `stencil`. They must stay DOM-free. `shell_mesher` uses only `THREE.ShapeUtils`; `exporters` uses `globalThis.fflate` only if present.
- **three.js r128** comes from `node_modules/three` (pinned `0.128.0`), loaded as globals, together with `examples/js` loaders. Do not upgrade casually: `examples/js` was removed in later versions.
- **Language:** all UI text, warnings and status messages are **Turkish**. Code identifiers are English. Comments are Turkish or English, so match the surrounding file.
- **Units:**
  - Lamp geometry and UI are in **cm**: lamp coordinates, shape params, depth `d`, light height `cz`, shadow radius `R`.
  - Meshes and STL are in **mm**: `ShellMesher` multiplies by `MM = 10`.
  - Print settings in the UI are mm: thickness, plate, LED seat, bed.
- **Lamp coordinates:** the room wall is the plane `z = 0`. The lamp body occupies `z ∈ [0, d]` and the LED sits at `(0, 0, cz)` with `cz = lightFrac·d`. The body outline polygon is the wall's **mid-surface** at `z = 0`, and taper scales it by `1 + k·z`. The one-piece STL is printed in these coordinates (base plate on the bed, z up).
- **Target image:** a `2048²` canvas covering `[-R, R]²` cm on the room wall, with +Y up in wall coordinates and image row 0 at the top. White = lit, black = shadow, and edges are **anti-aliased** on purpose (sub-pixel accuracy).
  - `outsideLit` = true for silhouettes (the area outside the image is lit) and false for legacy v1 designs.
  - The shadow can be rotated and offset (`d-rot`, `d-offx`, `d-offy`). `designer.makeWallToTarget()` maps wall → target.
- **Wall field:** `F[r * nc + c]` holds values in 0..1, and **> 0.5 means lit (cut away)**. Columns are arc-length `colS` around the outline, periodic, and every polygon vertex is a column. Rows `rowZ` are non-uniform: log-t spacing below the light and a few rows for the solid band above it.

## Invariants — do not break

1. **Meshes are watertight.** `wallMesh` keys every vertex by grid corner or grid edge, so neighbouring cells share vertices. Never emit per-cell duplicate vertices or T-junctions. `npm test` checks every edge is shared by exactly two oppositely oriented triangles and that volume is positive.
2. **Shapes are star-shaped around the axis and CCW.** `Shapes.make` checks this (`starShaped`). `offsetPolygon` drops folded vertices so offsets stay star-shaped. New shapes are just vertex generators in `CATALOG`.
3. **What the simulation shows is what gets printed.** The 2D simulation, the wall strip, the room texture, the bed mask and the accuracy metric all sample the **final field**, after bridges, roofs and hole filling. Never compute a preview from the raw target.
4. **Nothing floats.**
   - Solid islands are bridged (0-1 BFS through existing solid) or removed only if they are specks (< ~0.5 mm²).
   - In cap mount, a front rim not connected to the base sets `stats.rimFloating`, which shows a warning.
   - In flat mode with the 0.2 mm layer, islands are kept because the layer holds them.
5. **Preview-only meshes** (`previewOnly: true`, the transparent tube) never go into the STL or any other export. `toBinarySTL` and `ModelExport` filter them out.
6. **Settings flow:** a setting is a `SCHEMA` entry in `main.js` (id, type, label, unit, range, `showIf`, `note`). Then:
   - If it affects the field, read it in `designer.readParams()` and add its id to the listener list in `designer.js`.
   - If it only affects meshes, read it in `printOpts()` in `main.js`.
   - Saved designs store every non-`c-` setting id (`STATE_IDS`).
7. **The design file format is v2:** `{ version: 2, sliders: {id: value}, outsideLit, targetImage }`. v1 files (the old box designer) open as a rectangle body, cap mount, no ribs, `outsideLit = false`. Keep that path working.

## Physics and printing facts the code relies on

- **Magnification:** a feature on the room wall shrinks by `t = ρ / r` on the lamp wall. `ρ` is the distance from the lamp axis, `r` is the body radius in that direction.
  - The printer can't print lines much thinner than about 0.8 mm (2 × 0.4 mm nozzle). So the finest printable shadow detail is about `0.8 mm · ρ / r`; it gets coarse at the shadow edge.
  - Bigger body or smaller shadow means more detail. `main.js` → `detailLimitHtml()` and `optimizeDetail()` use this.
- **Penumbra:** blur ≈ `D · z_cut / (cz − z_cut)`, where `D` is the LED emitter size. Recommend single-chip LEDs (≤ 3 mm emitter), not bulbs.
- **Support-free upright printing** (`supportFree`, off by default; the default is upright with slicer supports):
  - Overhangs up to 60° from vertical, bridges up to 12 mm between two anchors, and cantilevers up to 2.5 mm print without supports.
  - Longer unsupported runs get a roof at the angle limit. This is checked on a raster with `Δz = Δs / tan(angle)`.
  - Roofs alter the shadow, so for very detailed art, flat panels + 0.2 mm layer (no roofs, no bridges) are usually better. The optimizer compares these options.
  - Roofs near the light are magnified hugely on the wall (radial ≈ ρ·t/cz). A wide lit shape far out (e.g. a crescent at ρ ≈ 45 cm on a 15 cm cylinder) leaves a ~1 mm rim above it that needs roofs, which show as saw teeth. That is physics, not a meshing bug: turn off support-free, enlarge the body, or shrink the shadow.
- **Target sampling:** `designer.makeSampler` reads a cached signed distance field (`WallField.signedDistance` / `smoothSampler`), not raw pixels. Raw sharp pixels make far edges stair-step because one wall cell covers many target pixels. Keep the SDF; the sign is exact (> 0.5 ⇔ lit pixel).
- **Tube mount:** the LED must be the lowest opaque point of the cap assembly. Anything opaque beside or below it blocks the near-horizontal rays that light the far wall. The "Gerçek gölge" (shadow map) view caught exactly this bug once, so use it to validate geometry changes.

## Pitfalls

- **Linux:**
  - Never trigger a native file dialog (GTK crashes with SIGTRAP after the first one). Opening goes through `filepicker.js`; saving writes to Downloads via `file:save`.
  - Electron aborts on the SUID sandbox. `npm start` already passes `--no-sandbox`.
  - npm 11 blocks install scripts, so the Electron binary may be missing; see Run.
- **AI model:** `isnet-general-use.onnx` (Apache-2.0, ~170 MB) downloads on first use to `<userData>/models/`. `u2netp` is the fallback. Only the desktop app has it; in browser mode the AI options are removed from the UI.
- **Performance:**
  - Field recompute is debounced (`setTimeout`, not rAF; rAF stalls in background windows).
  - "Çok yüksek" detail (≈650k cells) makes STL files of 40 MB or more.
  - The editor works on 2048² with 20 undo steps (~8 MB each).
- **Don't** reuse code from the MakerWorld "Light Shadow Art Generator". Its licence is MakerWorld Exclusive; this codebase only shares ideas (tube mount, chamfered panels, 0.2 mm layer) implemented independently.
- Keep `README.md`, this file and `docs/ARCHITECTURE.md` in sync when you change behaviour.
